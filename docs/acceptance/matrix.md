# Issue #10 十四项验收矩阵

所有场景都以 [操作手册](operations.md) 中的 `PF` 只读预检通过、`BR` 备份检查完成、
证据模板已初始化且当前没有未决恢复操作为共同前置条件。每项证据不得包含真实设备 ID、
序列号、账号、IP 或 `ruleId`。

| ID | #10 条目 | 验收目标 | 前置条件 | 操作 | 预期结果 | 证据类型 | 安全恢复步骤 |

| ACC-01 | 1 基线 CRUD 与目标授权同步 | 证明读、建、改、暂停、恢复、删除及授权同步可用 | PF、BR、一个受控目标和一条可删除测试规则 | 依次读取规则、新建规则、编辑、暂停、恢复、删除，并在读取结果中核对目标授权 | 每步返回成功且后续读取一致；删除撤销目标授权，暂停保留授权 | UI 截图、受控 API 读回摘要、规则与授权文件前置及后置哈希 | 立即停止新写操作；通过 LKG 或受控 API 恢复基线，读回并比对哈希 |

| ACC-09 | 9 RPC 拒绝错误签名包名和协议 | 证明认证和协议失败不泄露敏感数据 | PF、BR、仓库测试调用器或已批准测试夹具 | 分别以错误签名、错误包名、错误协议版本调用 RPC | 返回认证或协议错误；不返回规则内容、路径或其他敏感数据 | 脱敏 RPC 响应、错误码、日志哈希 | 移除测试调用器；不修改生产认证配置，读回确认无写入 |
| ACC-10 | 10 杀进程冷启动和面板重启恢复 | 证明跨进程状态与故障态恢复 | PF、BR、可复现的受控进程环境 | 人工从系统最近任务结束 VoiceAssist，重新打开入口并冷启动 Provider，再重启面板 | 状态和故障态按设计恢复；不得把未知误报为空数据；已持久故障不能被清除 | 分阶段截图、受控 API 读回、过滤日志 | 重新打开面板并只执行重新检测或受控回滚；仍异常则保持只读并中止 |

## #10 第 15 条横切证据记录

Issue #10 第 15 条是证据记录要求，不是第 15 个功能场景。每次执行必须：

- 使用 [证据模板](evidence-template.md) 记录设备型号、系统版本、VoiceAssist 与 MiLink 版本、
  APK SHA-256、证据时间、日志归档、Issue 链接、执行人和结果。
- 为 `ACC-14` 记录 `forwardId` 的脱敏哈希与尝试次数，并证明 `attempt=1`。
- 将证据追加到 Issue #10 的验收记录；本工单不关闭 Issue #10 或 Issue #11。
