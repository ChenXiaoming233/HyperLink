# HyperLink 开发与测试

当前阶段包含可离线验证的模块骨架、领域接口、RPC 纯层、fake 场景面板、fake 安全写入
事务层、fake 写入失败恢复、fake 结构化规则编辑器和 fake 规则生命周期控制。它不包含真实 LSPosed Hook、
VoiceAssist Provider 接线或设备级兼容性验收。

## fake 只读面板

场景展示只调用内存中的 fake store，不读取 VoiceAssist 规则文件、权限 store、
Provider 或 `notification-subscriptions.json`。所有 fake 设备名、
设备 ID、来源、规则 ID 和 DSL 示例均为合成占位（如 `Demo-PC`、`demo-target-a`、
`demo-rule-1`），不包含真实设备关联信息。面板提供正常、过期缓存、空数据、读取失败、
系统通知使用权缺失和已撤销演示场景，并可切换 fake 活体状态。

只读快照保留目标的类型、在线、可达、目标授权和接收能力，以及规则的原始顺序、
`ruleId`、来源、目标、上游状态、规则摘要和完整 DSL。面板仅展示具备接收能力的
PC、PAD、MAC 目标；手机等其他类型会被过滤。目标授权与系统通知使用权分别展示，
离线目标保留显示并明确说明不会排队或自动重试。

过期快照会标记“缓存快照已过期”，且不能载入写入流程。`NotificationFlowService` 只有
`readSnapshot()` 操作；“已启用”或 fake 快照成功均不代表通知已经送达，也不代表真实
MiLink/VoiceAssist 已接线。未激活、进程不可达或能力不足时仍展示各自原因，不把未知
列表误写成“空数据”；读取失败时列表区显示“无法确定”，而不是断言没有设备或规则。
在线和可达分别展示：在线但不可达与当前离线使用不同提示。
已暂停规则若指向缺失或不可接收的目标，会显示“已暂停（目标不可用，恢复前需处理）”，
避免同时出现“已暂停”和“受阻”的冲突状态。

## fake 安全规则写入事务

`domain.write` 提供目标选择、首次目标授权确认和离线警告流程，并通过
`SafeNotificationRuleWriter` 创建“所有符合条件的通知”独占规则。规则按来源设备和目标
设备 upsert；同一组合重复创建时复用原 `ruleId`，不会生成重复规则。创建结果会保留系统
通知使用权、目标授权和在线/可达能力相关的限制说明。

能力探测模型分别检查类、构造器、方法、字段、状态值和 DSL 结构。版本不在已验收集合中
但所需能力全部通过时仍允许写入，同时返回“兼容性未经完整验收”；能力缺失时拒绝写入。
兼容性提示同时参考能力探测结果和快照的 `compatibilityUnverified`，任一为未验收都会
显示“兼容性未经完整验收”。写入前还会逐条检查完整规则快照中的状态值、DSL 根结构、
规则分支、条件字段、操作符和值结构；只要存在未知字段或不可表达 DSL，整次写入即进入
只读，不会执行部分写入；超出嵌套深度上限的 DSL 同样按不可表达处理。gateway 的汇总
布尔只作为额外保护，不替代实际结构校验。

每次写入前先保存完整 LKG，包括原始规则顺序、`ruleId`、筛选 DSL、状态、目标显示名、
设备类型、在线、可达、接收能力、目标授权和系统通知使用权。写入通过进程内共享锁串行
执行，同一 fake gateway 的多个 writer 实例也不会互相覆盖；该锁只负责 writer 串行化。
提交还携带初始 store 版本和预期规则，fake gateway 在 store monitor 内执行乐观并发校验。
版本或规则内容已变化时拒绝本次写入并 fail-closed，不会用旧候选覆盖外部规则变更。

写入后同时校验 fake store 回读与序列化结果中的目标规则、未修改规则、数量、`ruleId`
唯一性、顺序和 DSL，并比较完整目标状态及系统通知使用权。写入期间权限或目标状态发生
变化时，只回滚本次 writer 写入的规则，保留外部权限和目标状态，然后进入持久只读故障态；
不得用 LKG 将并发撤销的权限写回为已授权。若无法在保留外部状态的前提下验证规则回滚，
同样保持只读。其他写入或安全结构校验失败时，也仅通过 LKG 回滚规则并再次读取验证。
无法验证回滚时，将只读故障态写入 fake store；即使故障态持久化调用抛异常，同一
`FakeRuleStore` 的内存只读闸门仍会阻止后续新 gateway/writer 写入。新建 gateway 或
writer 仍会读取该故障态并 fail-closed；显式规则恢复不会自动清除故障态，并在故障态下
同样失败。

该事务层只使用 `FakeRuleStoreGateway`、`FakeLastKnownGoodStore` 和 Demo/demo 合成
标识，不访问真实 VoiceAssist 规则文件、权限 store、Provider 或设备，不提供真实写入
降级、任意反射入口或生产环境文件写入。`FakeRuleStore` 只模拟持久 store 的共享故障态，
不模拟文件格式、进程重启后的磁盘持久化或真实原子性；真实持久化仍属于 #5/#9。

## fake 写入失败恢复与受控调试

`RuleWriteRecoveryController` 只包装 fake store 的新建与结构化规则写入。首次写入后结构校验
失败时，它会保留第一次写入前的 `RuleLkg` 与失败快照，不回滚也不让后续失败覆盖 LKG；恢复
模型推荐立即回滚，同时提供默认最多一次的受控重试。受控重试前必须重新读取 store，并再次
检查能力、连接、来源、目标授权、未知字段、不可表达 DSL 和当前快照安全性；当前状态不安全
时禁止重试。重试成功后才结束操作；重试再次失败会自动执行规则回滚并验证，不再次询问。

立即回滚或自动回滚验证成功后恢复第一次写入前状态，并在恢复视图中保留原始失败原因；系统
不会自动重放原写入。回滚无法验证时进入 fake 持久只读故障态，只提供“重新检测”和“再次
尝试回滚”，不提供强制写入开关。故障态重试回滚使用专用 gateway 操作，只有恢复结果与 LKG
完全匹配并通过回读验证后才清除故障态。

未知 VoiceAssist 版本但能力探测通过时，正常写入、失败恢复和重试视图都会显示“兼容性未经
完整验收”。高级区的调试开关默认关闭，并始终展示高风险警告。开启后只取消默认重试次数与
重试前状态验证，不会绕过能力探测、认证、未知字段/DSL 禁写、LKG、写入后校验或回滚保护；
调试模式在写入成功、回滚、页面退出或进程重启后自动关闭。所有恢复操作仍只作用于 Demo 合成
数据和独立内存 fake gateway，不存在真实 Provider、权限、设备或规则文件接线。

## fake 结构化规则编辑器

设置页只创建一份内存 `FakeRuleStoreGateway`/`FakeRuleStore`，并把它同时提供给只读
场景面板、结构化编辑器和 `RuleLifecycleController`。场景切换通过
`replaceSnapshot()` 更新同一份共享快照，因此编辑器暂停、恢复或删除后，页面规则列表
会重新读取同一 store，不会继续显示初始 immutable snapshot。保存按钮只在用户显式点击后
调用安全写入链路；页面不会自动保存，也不存在真实路径降级、认证绕过或能力探测绕过。
所有目标、规则、应用名称和包名均为 `Demo-*` / `demo.*` 合成数据，不读取真实已安装应用、
图标、VoiceAssist 规则、权限 store、Provider 或设备。首次使用未授权目标时必须展示目标名
和授权含义，只有用户确认后才调用 `confirmAuthorization()`；拒绝会取消保存。离线目标
同样要求显式确认，不能作为普通成功路径静默继续。

场景读取失败时，共享生命周期编辑器整体隐藏，所有保存、暂停、恢复、删除和撤销入口都会
短路拒绝，不会保留旧可写快照继续操作；共享 store 恢复可读后才重新显示。`FakeRuleStore`
已处于持久只读故障时，`replaceSnapshot()` 必须把同一故障继续写入替换后的快照，场景切换、
新建 gateway 或 Activity 重建都不能清除该故障，后续写入继续 fail-closed。

IM、焦点通知和短信验证码只是临时编辑模板。展开后分别变成 `app in`、`isIsland is true`
和 `isVerifyCode is true` 条件，多个模板生成同一 AND 组下的多个 OR 规则分支；保存的 DSL
不包含预设类型。编辑器支持 AND 组、OR 分支和条件的新增、删除、移动与编辑，应用条件支持
`in` / `not_in`，布尔条件支持 `isIsland is true/false` 与
`isVerifyCode is true/false`。高级区域支持 `sender` / `text` 的
`regex` / `not_regex` 编辑；正则使用 Java `Pattern` 做真实语法检查，捕获语法异常并只展示
安全文案，非法正则不能应用或保存。

规则摘要始终由 andGroups → branches → conditions 结构生成，用户不能手写 `ruleText`；
筛选结构变化会更新摘要，仅状态变化不会改变摘要。编辑现有规则时按 source+target upsert，
并由 `SafeNotificationRuleWriter` 保留原 `ruleId`、状态和 `createdAt`，不会产生重复规则。
一次保存后，其他规则的数量、顺序、`ruleId`、状态和 DSL 保持不变；回读校验仍由
#15/#16 的安全写入链路完成。

应用选择器通过 fake `AppCatalog` 提供搜索、多选、名称和图标占位。默认仅展示可启动应用
和规则已引用应用，可切换到全部已安装应用；已引用但未安装的应用继续保留并标记“未安装”，
没有可解析名称时直接显示包名。应用选择结果绑定当前 AND 组 / OR 分支中的当前 app
条件，载入规则或切换条件时只载入该条件的包集合，不会把所有分支包并成全局选择；应用
多选只替换当前 app 条件，其他分支保持不变。

安全写入成功后，编辑器逐条展示 `RuleCreationResult.notes`，包括离线、目标未授权、
系统通知使用权和兼容性未验收等提示，不以通用成功文案覆盖。完整快照若已存在重复
source+target 规则，writer 会进入持久只读故障态且不执行 upsert，避免静默删除重复规则。
编辑器载入和保存前还会检查整份规则模型；任意规则出现未知字段、未知状态或不可表达
DSL 时，整份模型进入只读，而不是只禁写当前规则。界面展示具体规则和原因，禁用全部编辑
与保存入口，并提供“重新检测规则模型”；不提供强制保存。重新检测只重新读取 fake
gateway，只有快照修复且校验通过后才恢复可编辑状态。

## fake 规则生命周期

结构化编辑器通过 `RuleLifecycleController`、`SafeNotificationRuleWriter` 和
`FakeTargetPermissionGateway` 演示暂停、恢复、撤销与删除。暂停只把原规则状态改为
`paused`，恢复只改回 `active`；两者都复用原 `ruleId`、筛选 DSL、摘要、目标、创建时间和
目标授权，并沿用安全写入器的 LKG、串行写入、乐观并发与回读校验，不直接修改 JSON。
操作成功返回新 UI 模型和 `RuleUndoToken`，编辑器的演示撤销窗口为 10 秒；token 带单调
序号和到期时间，过期、被新操作替换或已被消费的撤销请求会失败且不写入。撤销写入失败时
不会提前消费 token；stale、授权冲突、目标换绑等冲突恢复后可重试，只有写入成功或确认
过期才清除 token。

删除必须由 `requestDelete()` 生成一次性确认对象，确认文案明确删除会撤销目标授权；
取消确认不会调用规则写入或权限 gateway。确认后先从 fake store 删除规则，再通过
`TargetPermissionGateway` 撤销目标授权。权限撤销失败时规则删除已发生，但操作返回失败，
并写入只读故障态；UI 显示阻断错误，不伪造完整成功。

生命周期操作会携带 UI 上次观察到的目标授权值。外部授权变化与预期不一致时，安全写入器
拒绝变更并显示阻塞错误，不会静默重新授权、写回旧授权或覆盖外部状态。系统通知使用权
只从 fake 快照检测；`MISSING` / `REVOKED` 时活动规则显示受阻，并提供纯层可测的
`NotificationAccessSettingsIntentSpec`，只读面板据此打开系统设置页。该入口不调用任何
授权写入 API。暂停、恢复、删除和撤销还统一要求快照非 stale、连接状态可写、能力探测
通过、目标授权和系统通知使用权满足；任一条件失败时只显示阻断原因，不执行写入。所有规则、
目标、设备名和授权均来自 Demo/demo 合成数据。

## 构建 APK

```bash
./gradlew --no-daemon assembleDebug
```

生成的 APK 可安装并打开独立的 fake 状态面板与结构化编辑器。LSPosed 元数据与
`xposed_init` 仅建立模块加载骨架；当前模块不会安装任何方法 Hook，也不会改变 MiLink 或
VoiceAssist 行为。

## 当前边界

- `MiLinkEntryExtension` 是保留的未接线扩展点，不存在本地降级入口。
- 尚无生产用的 `CallerEvidenceResolver`；它必须由平台 UID 归属、包名和签名采集实现，
  且解析结果的 UID 必须与 Binder 调用方 UID 一致。
- 尚无生产 Provider `call()` 适配器或真实快照 DTO 序列化。
- `RuleStoreGateway`、`LastKnownGoodStore` 目前只有 fake 实现；尚未接入 VoiceAssist
  同进程 store 或应用私有目录的持久化 LKG。`FakeRuleStore` 的共享故障态只在 JVM 内
  模拟持久化，重启恢复仍需 #5/#9 的真实持久化设计。
- fake 状态、单元测试和编译成功均不代表真实 MiLink/VoiceAssist 集成完成。
