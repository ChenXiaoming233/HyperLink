# 06: 完整 DSL、正则与不可表达规则保护

**What to build:** 高级用户能够编辑 sender/text 正则和完整的规则分支、条件组合；复杂规则始终得到准确摘要。无法表达的规则必须只读，不能因编辑一条规则而重序列化丢失其他规则。

**Blocked by:** 05

**Status:** ready-for-agent

- [ ] 在高级区域提供 sender/text 的 regex 与 not_regex 编辑和校验。
- [ ] 支持完整 andGroups、规则分支和条件的增加、删除、排序与编辑。
- [ ] 复杂组合生成准确但可较通用的规则摘要，不要求用户补写文案。
- [ ] 支持 `app in/not_in`、`isIsland is`、`isVerifyCode is` 的全部现有合法组合。
- [ ] 存在未知字段、未知状态或不可表达 DSL 时，整份规则文件进入只读，而不是仅禁写当前规则。
- [ ] 只读状态说明具体原因，并提供重新检测入口，不提供强制保存。
- [ ] 编辑一条规则后，未修改规则的数量、顺序、`ruleId`、状态和 DSL 保持不变。
- [ ] 测试覆盖 regex、复杂摘要、完整 DSL、未知字段禁写和未修改规则不变。
- [ ] 设备验收确认高级规则可由上游 guard 接受或在上游拒绝前被面板阻止。
