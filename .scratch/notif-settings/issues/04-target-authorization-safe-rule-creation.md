# 04: 目标授权与安全创建规则

**What to build:** 用户能够选择可接收通知的目标，完成首次目标授权，并在离线或未知兼容版本状态下安全创建一条“所有符合条件的通知”规则。第一次实际写入开始就具备完整的数据保护链路。

**Blocked by:** 03

**Status:** ready-for-agent

**Implementation note:** 这是本轮最大的纵向切片，刻意同时覆盖目标授权、规则创建 UI、RPC/适配器写入与事务保护，避免机械拆成“事务层”和“创建 UI”而失去端到端可验证性。若实现时发现单上下文无法完成，只在确认“目标授权可以独立成为用户流程”后拆分；否则优先细化实现步骤和验收标准，不破坏纵向完整性。

- [ ] 提供目标选择、首次授权确认和离线配置警告。
- [ ] 创建“所有符合条件的通知”独占规则，并明确其仍受系统闸门与目标能力限制。
- [ ] 按 source+target upsert，保证同一目标不产生重复规则。
- [ ] 写入前执行关键类、构造器、方法、字段、状态值、DSL 和序列化能力探测。
- [ ] 写入前检查整份原始规则文件；存在无法表达的字段或 DSL 时整体禁写。
- [ ] 每次写入前保存应用私有目录中的完整 LKG 快照，写入与状态操作串行执行。
- [ ] 写入后重新读取 store 和实际文件，校验目标规则、未修改规则、数量、`ruleId` 唯一性、顺序和 DSL。
- [ ] 基础结构失败时能够从原始 LKG 自动回滚并验证回滚结果。
- [ ] 未知版本在能力探测通过时允许创建，并在 UI 标记“兼容性未经完整验收”。
- [ ] 测试覆盖授权确认、离线创建、重复创建、未知字段禁写、快照失败、回读失败和基础回滚。
- [ ] 设备验收确认规则通过 store API 热生效，且未修改规则保持不变。
