# 手机端通知流转设置面板

Status: ready-for-agent

## Problem Statement

手机到 PC/平板的通知流转已经由小爱 A2A 实现，但用户只能通过小爱对话管理规则，无法在符合系统习惯的跨设备设置入口中查看规则状态、选择目标、编辑筛选条件、暂停、恢复或删除规则。

直接编辑规则文件无法保证运行中的转发流程立即生效，还可能因上游解析和重序列化造成数据丢失。用户需要一个位于 MiLink 跨设备设置体系中的入口，打开独立设置面板，并通过受控通道管理 VoiceAssist 中的唯一权威规则状态。

## Solution

在 MiLink 跨设备设置页增加一个“通知流转”入口，打开模块自带的独立设置面板。面板负责规则和授权的用户界面，不直接读写 VoiceAssist 文件。

VoiceAssist 进程内加载一个窄数据适配器。面板通过现有导出 ContentProvider 的 `call()` 通道调用固定领域操作，由适配器访问同一进程内的规则 store、权限 store 和相关内部 API。

首版支持：

- 查看目标设备和现有规则。
- 新建、编辑、暂停、恢复、删除规则。
- 管理目标授权，并检测系统通知使用权状态。
- 使用快捷预设和完整结构化 DSL 编辑筛选条件。
- 在能力探测允许时对未知 VoiceAssist 版本读取和写入，同时明确标记兼容性尚未完整验收。
- 通过 LKG 快照、串行写入、回读校验和尽力回滚降低结构损坏风险。

## User Stories

1. 作为使用手机到 PC 通知流转的用户，我希望从 MiLink 跨设备设置页进入通知流转面板，以便在系统习惯的位置管理功能。
2. 作为独立使用该模块的用户，我希望从模块桌面图标打开同一设置面板，以便不经过 MiLink 也能访问。
3. 作为用户，我希望面板启动后显示所有可管理的规则和目标，以便确认当前哪些设备会接收通知。
4. 作为用户，我希望只看到具备通知转发能力的 PC、平板或 Mac 目标，以便避免选择不受支持的设备。
5. 作为用户，我希望同时看到目标在线、离线、授权和转发能力状态，以便区分“规则已开启”和“当前可达”。
6. 作为用户，我希望离线目标仍可配置，并看到“不会排队或自动重试”的明确警告，以便提前准备规则而不误以为通知一定送达。
7. 作为用户，我希望查看每条规则的目标、状态、规则摘要和筛选条件，以便理解规则实际范围。
8. 作为用户，我希望从“全部符合条件的通知、IM、焦点通知、短信验证码”等预设开始创建规则，以便减少重复配置。
9. 作为用户，我希望预设只是可编辑的快捷模板，而不是固定套餐，以便在套用后继续调整。
10. 作为用户，我希望多个具体模板按 OR 规则分支组合，以便表达“IM 或焦点通知或验证码”等组合。
11. 作为用户，我希望“所有符合条件的通知”是独占模式，以便明确表示不添加规则级筛选。
12. 作为用户，我希望界面说明“所有符合条件的通知”仍受系统闸门和目标能力限制，以便不把它误解为所有通知必然送达。
13. 作为用户，我希望编辑规则分支和条件，以便覆盖应用集合、焦点通知、验证码、发送者和文本条件。
14. 作为用户，我希望发送者和文本正则位于高级区域，以便普通操作保持简洁而高级用户仍可使用完整 DSL。
15. 作为用户，我希望选择多个应用，以便一条规则覆盖一组通知来源。
16. 作为用户，我希望应用选择器支持搜索、图标和名称，以便快速找到目标应用。
17. 作为用户，我希望默认应用列表包含可启动应用和当前规则已引用应用，并可切换显示全部已安装应用，以便兼顾简洁和完整性。
18. 作为用户，我希望规则中已引用但当前未安装的应用继续保留并明确标记，以便编辑规则时不会静默丢失它们。
19. 作为用户，我希望无法解析名称的包显示原始包名，以便仍能识别和保留。
20. 作为用户，我希望规则摘要由结构化条件自动生成，以便保存后官方列表和语音回复中的描述与真实条件一致。
21. 作为用户，我希望复杂组合也自动生成准确但可能较通用的摘要，而不需要手动补写文案，以便保存流程不被打断。
22. 作为用户，我希望修改筛选条件时能预览规则摘要，以便确认保存后的可读说明。
23. 作为用户，我希望普通规则保存在编辑页点击保存后直接提交，以便避免重复确认。
24. 作为用户，我希望暂停和恢复立即执行并提供短时撤销，以便低风险操作保持流畅。
25. 作为用户，我希望删除规则前确认一次，并明确知道目标授权也会被撤销，以便避免误删和隐性授权残留。
26. 作为用户，我希望建立或恢复规则前检查目标授权，并在首次授权时看到明确用途说明，以便知情授权。
27. 作为用户，我希望暂停规则时保留规则、筛选条件、`ruleId` 和目标授权，以便恢复时无需重新配置。
28. 作为用户，我希望恢复暂停规则时使用原 `ruleId`，以便规则身份保持稳定。
29. 作为用户，我希望删除规则后对应目标授权被撤销，以便清理不再需要的转发权限。
30. 作为用户，我希望普通筛选条件修改不重复弹出目标授权确认，以便减少打扰。
31. 作为用户，我希望目标授权被外部改变时看到状态不一致错误，而不是后台静默重新授权，以便保持权限可见。
32. 作为用户，我希望面板检测系统通知使用权，并在缺失时跳转系统设置页，以便授权始终由系统界面完成。
33. 作为用户，我希望面板不通过隐藏 API 授予或撤销系统通知使用权，以便权限边界清晰。
34. 作为用户，我希望系统通知使用权被外部撤销后，受影响规则显示受阻，不被错误显示为正常转发。
35. 作为用户，我希望已有规则可以无损加载，以便不会因为打开编辑器导致 count、`ruleId`、状态、顺序或条件变化。
36. 作为用户，我希望当前版本无法表达的未知字段或 DSL 存在时整份规则文件禁止写入，以便避免上游重序列化清理未知字段。
37. 作为用户，我希望无法表达的规则明确显示为只读，以便知道问题来自模块兼容性而不是规则本身。
38. 作为用户，我希望未知 VoiceAssist 版本在能力探测通过时仍可读写，以便目标应用升级后不必等待严格版本适配。
39. 作为用户，我希望未知版本明确标记“兼容性未经完整验收”，以便不把能力探测通过误解为完全兼容。
40. 作为用户，我希望能力探测失败时面板只读或不可用，而不是冒险调用不存在的内部 API。
41. 作为用户，我希望认证失败、协议不匹配或适配器不可用时面板 fail-closed，以便不会退回到直接文件写入或本地镜像。
42. 作为用户，我希望每次写入前自动保存完整 LKG 快照，以便结构性失败后能够恢复。
43. 作为用户，我希望写入和状态修改串行执行，以便避免并发操作互相覆盖。
44. 作为用户，我希望写入后自动回读 store 和实际规则文件进行校验，以便结构性问题立即被发现。
45. 作为用户，我希望第一次结构校验失败后选择立即回滚或受控重试一次，以便在安全默认与人工判断之间取得平衡。
46. 作为用户，我希望重试前检查当前状态，状态不安全时禁止重试，以便避免扩大部分写入。
47. 作为用户，我希望重试再次失败后直接自动回滚，不再重复询问，以便失败路径保持确定。
48. 作为用户，我希望回滚无法验证时进入持久只读故障态，即使进程重启也不能继续写，以便阻止未知损坏扩散。
49. 作为用户，我希望故障态只提供重新检测和再次尝试回滚，不提供强制写开关，以便没有绕过安全闸门的入口。
50. 作为开发者，我希望存在一个高风险调试开关，以便在排障时允许多次手动重试。
51. 作为开发者，我希望调试开关默认关闭、显示警告并放在高级区域，以便避免普通用户误用。
52. 作为开发者，我希望调试模式跳过重试前验证并允许无条件继续发起原写入，同时不保证成功，以便满足排障需要。
53. 作为开发者，我希望调试模式不绕过初始能力探测、未知字段禁写、认证、快照和写入后校验，以便仅放宽重试边界。
54. 作为用户，我希望调试模式在成功、选择回滚、页面退出或进程重启后自动关闭，以便危险模式不会长期残留。
55. 作为用户，我希望 Provider 冷启动、VoiceAssist 被杀或面板重启后仍能看到正确规则状态，以便跨进程架构不会造成可见状态丢失。
56. 作为用户，我希望编辑一条规则时未修改规则的 `ruleId`、状态、筛选和顺序保持不变，以便规则文件变更范围可预测。
57. 作为用户，我希望一条受控通知只产生一次转发尝试，以便规则编辑不会造成重复发送。
58. 作为维护者，我希望 RPC 只暴露固定领域操作，以便不把目标进程变成通用反射或文件操作入口。
59. 作为维护者，我希望调用方通过 UID、包名、签名证书和协议版本校验，以便未经授权的应用无法读取规则或设备信息。
60. 作为维护者，我希望所有失败都有稳定错误码和用户安全消息，以便 UI、测试和日志可以一致处理。

## Implementation Decisions

### 进程与组件边界

- MiLink 只注入跨设备设置入口，点击后启动独立通知流转设置面板；MiLink 不读写规则。
- 独立面板拥有自己的设置 UI、规则编辑器、RPC 客户端和只读展示缓存。
- `com.miui.voiceassist` 内只加载窄数据适配器，适配器访问同进程内的规则 store、权限 store、设备信息和相关内部 API。
- 规则与目标授权的唯一权威状态位于 VoiceAssist store。面板本地最多保存最近一次成功读取的只读快照，并明确标记过期；不能基于过期快照写入。
- 面板、适配器不可用、认证失败、协议版本不匹配、能力探测失败或未知字段禁写时，必须 fail-closed。
- 具体 MiLink 页面注入点和复用的 VoiceAssist 导出 ContentProvider 在实现阶段定点确认，但不得改变已确定的职责边界。

### 跨进程契约

- 面板与适配器通过现有导出 ContentProvider 的 `call()` 建立同步窄 RPC，不新增目标 APK manifest 组件。
- 适配器校验调用方 UID、包名和签名证书；认证失败不返回规则、设备或权限数据。
- 每次请求携带 RPC 协议版本。版本不匹配立即拒绝。
- RPC 使用统一 JSON envelope，包含成功状态、稳定错误码、用户安全消息、响应数据和状态版本。
- 公开操作限定为：读取能力与兼容状态、读取完整领域快照、创建或更新规则、暂停或恢复规则、删除规则、变更目标授权。
- RPC 不暴露任意反射、类名、方法名、文件路径、原始 JSON 写入或通用命令执行。
- 适配器内部串行执行写入，一次只允许一个规则操作。

### 规则模型

- 同一 source 与 target 只允许一条规则；新增和更新均按 source+target upsert。
- 更新保留原 `ruleId`、状态和创建时间，只更新筛选条件、来源、目标及更新时间中实际变化的字段。
- 规则状态继续使用上游字符串模型；首版新增持久化 `paused` 状态。发送链路只读取 `active`，因此 `paused` 不参与转发。
- 暂停不删除规则、不撤销目标授权、不重新生成 `ruleId`。
- 恢复把同一规则状态改回 `active`。
- 删除规则是独立操作；删除同步撤销该目标的授权，并在确认文案中说明。
- 首版不改变 `unauthorized` 的业务含义，不能用它表示用户主动暂停。

### 规则编辑器

- 编辑器完整表达当前支持的 DSL：`andGroups` 之间为 AND，规则分支之间为 OR，分支内条件之间为 AND。
- 条件字段支持 `app in/not_in`、`isIsland is`、`isVerifyCode is`、`sender regex/not_regex`、`text regex/not_regex`。
- 提供“全部符合条件的通知、IM、焦点通知、短信验证码”等可编辑预设。
- 多个具体预设生成多个 OR 规则分支。
- “所有符合条件的通知”是独占模式，不添加规则级筛选，并提示仍需经过发送链路闸门。
- `app` 选择器支持搜索、多选、图标和名称；默认展示可启动应用及规则已引用应用，可切换显示全部已安装应用。
- 规则中已引用但未安装的应用必须保留并标记；无法解析名称时显示包名。
- `sender` 与 `text` 正则只在高级区域暴露。
- `ruleText` 是只供人阅读的规则摘要，不参与规则匹配，也不能被解析回条件。
- 支持的 DSL 始终自动生成摘要；复杂组合生成准确但可较通用的摘要，不要求用户手动补充文案。
- 只改变暂停、授权或状态时保留原规则摘要；筛选条件变化时重新生成摘要。

### 无损读取与写入门槛

- 读取必须完整还原规则数量、顺序、`ruleId`、状态、来源、目标、筛选条件、摘要和权限信息。
- 不自动迁移、不自动规范化、不清理未知字段。
- 写入前检查整份原始规则文件。只要任意规则或任意层级存在当前模型无法表达的字段、状态或 DSL，整个写入功能进入只读。
- 检查范围必须覆盖完整文件，而不是只检查用户正在编辑的规则，因为上游写盘会重序列化完整规则列表。
- 通过 hook 上游序列化逻辑来保留未知字段属于后续增强，不是首版目标。

### 授权与权限

- 目标授权与系统通知使用权是两个独立状态。
- 新建规则或恢复暂停规则前，目标必须已授权。
- 首次目标授权由面板明确询问后，由适配器调用权限 store 授予。
- 暂停不撤销目标授权；删除规则同时撤销该目标授权。
- 普通筛选条件修改不重复要求目标授权。
- 外部改变导致目标授权与规则状态不一致时，面板显示阻塞错误，不静默重新授权。
- 系统通知使用权只检测状态并跳转系统设置页；面板不调用隐藏授权或撤销 API。
- 系统通知使用权缺失或外部撤销时，受影响规则显示受阻；面板不能继续宣称转发正常。

### 设备与离线行为

- 可管理目标仅包括具备通知接收能力、且类型为 PC、PAD 或 MAC 的设备。
- 设备展示至少包含在线、可达、目标授权和接收能力状态。
- 离线目标仍可配置和保存规则。
- 离线状态必须警告“当前不可达，发送不会排队或自动重试”。
- “规则已启用”不能表达为“通知已送达”。
- 已有规则指向当前离线设备时必须继续可见。

### LKG 快照与事务

- LKG 快照由 VoiceAssist 适配器持有，保存在 VoiceAssist 应用私有目录。
- 每次写入前同步读取完整规则和权限状态，保存最近一份已确认可读取的 LKG。
- 快照至少包含所有规则、`ruleId`、筛选条件、状态、目标授权、时间、目标版本和 schema 探测结果。
- LKG 不提供给普通面板文件接口；面板只能通过受认证 RPC 触发写入和回滚。
- 写入前执行能力探测，包括关键类、构造器、方法签名、字段、状态值、DSL 结构和序列化解析能力。
- 未知 VoiceAssist 版本不因版本号本身被禁止写入；能力探测通过且具备完整 LKG 时允许读写。
- 未知版本必须在 UI 显示“兼容性未经完整验收”，不得宣称完全兼容。
- 写入后重新读取 store 和实际规则文件，校验目标规则、未修改规则、规则数量、`ruleId` 唯一性、顺序和 DSL 结构。

### 失败、重试与故障态

- 第一次结构校验失败后展示弹窗，推荐立即回滚，也可选择受控重试一次。
- 默认模式重试前重新读取并校验当前状态；状态不安全时禁止重试。
- 重试始终以第一次写入前的 LKG 为回滚目标，不能用失败后的中间状态覆盖 LKG。
- 重试再次失败后不再次询问，直接自动回滚。
- 回滚验证成功后恢复原状态并显示失败原因；不自动重放原写入。
- 回滚无法验证时进入持久只读故障态。该状态必须跨页面重启和 VoiceAssist 进程重启保持。
- 只读故障态只提供重新检测和再次尝试回滚，不提供强制写开关。

### 调试重试

- 高级区域提供高风险调试开关，默认关闭。
- 开启时必须展示可能覆盖或放大异常结构的警告。
- 调试开关只取消重试次数上限和重试前验证，不绕过初始能力探测、认证、未知字段禁写、LKG 快照和写入后校验。
- 开启后，每次失败均可选择立即回滚或继续手动重试，重试次数不限。
- 用户继续手动重试时无条件发起原写入，但不能承诺必然成功。
- 成功、选择回滚、页面退出或 VoiceAssist 进程重启后自动关闭调试开关。

### 错误与用户状态

- 适配器返回稳定错误码、用户安全消息和可供诊断的非敏感上下文。
- 认证失败不回显规则、设备或权限信息。
- 过期缓存、兼容性未经完整验收、目标离线、通知读取受阻、持久只读故障态必须使用不同用户状态。
- 面板不通过本地删除、直接文件改写或忽略校验来“修复”适配器错误。

## Testing Decisions

测试只验证外部可观察行为，不依赖私有实现细节、内部调用顺序或不稳定混淆类名。

### 主接缝：NotificationFlowService

- 面板依赖固定的领域接口，生产实现使用 ContentProvider RPC，测试实现使用内存 fake。
- 覆盖规则列表、编辑、预设、暂停、恢复、删除、目标授权、离线提示、过期缓存和各类故障态。
- 断言用户看到的状态、可用操作、错误消息和最终领域数据。
- RPC 协议测试直接调用 ContentProvider 的 `call()` handler，验证协议版本、认证、错误 envelope、序列化边界和状态版本。

### 次接缝：VoiceAssistRuleGateway

- 目标进程中的 store、权限 store、文件读取、能力探测和实际落盘通过该高层 gateway 封装。
- 使用 fake gateway 测试 LKG 创建、串行写入、未知字段禁写、写入后回读校验、受控重试、调试重试、回滚和持久故障态。
- 能力探测测试使用可替换的能力描述，不依赖真实混淆类被加载。
- 回滚失败测试必须区分“已回滚并验证”和“无法验证回滚结果”。

### Hook 接线

- MiLink 入口、ContentProvider 接管和真实 VoiceAssist 反射绑定只做设备级 smoke test。
- smoke test 验证入口可启动面板、认证通过的调用可达、认证失败被拒绝、冷启动可恢复、VoiceAssist 被杀后不出现部分状态。
- 不把 Xposed 细节扩散到领域层测试。

### 验收矩阵

1. 基线版本完成读、建、改、暂停、恢复、删除及目标授权同步。
2. 现有三条规则加载后，数量、`ruleId`、状态、目标、DSL、规则摘要和顺序无损。
3. 编辑按 source+target upsert，不生成重复规则；恢复不改变 `ruleId`。
4. 删除规则同步撤销目标授权；暂停保留授权。
5. 目标离线时仍可保存，UI 明示不可达且无队列或重试。
6. 系统通知使用权缺失或撤销时，只提示并跳转系统设置页。
7. 快照读取或写入失败时禁止继续写。
8. 结构校验失败后可选择回滚或受控重试；回滚无法验证时持久只读。
9. RPC 拒绝错误签名、错误包名和协议版本不匹配，且不泄露敏感数据。
10. VoiceAssist 被杀、Provider 冷启动、面板重启后状态与故障态正确恢复。
11. 未知版本能力探测通过时写入并显示“兼容性未经完整验收”；探测失败时只读或不可用。
12. 未知字段或无法表达 DSL 存在时整份规则文件禁写。
13. 编辑一条规则后，未修改规则的 `ruleId`、状态、筛选和顺序保持不变。
14. 用一条受控测试通知观察日志，确认只产生一次转发尝试。

仓库目前没有既有应用测试或可复用测试先例，以上接缝均为新建设计。

## Out of Scope

- MiLink 手机到手机的通知流转。
- PC 接收端的通知展示、点击、投屏和源应用拉起行为。
- 平板实机适配。
- 通知删除从手机同步到 PC。
- 转发历史、审计日志和每一条通知的可查询送达记录。
- 离线队列、自动重试和发送失败后的补发。
- 通过面板直接授予或撤销系统通知使用权。
- 直接修改规则 JSON 作为写入通道。
- 自动迁移、自动规范化或静默修复未知规则结构。
- 修改上游 `ignoreUnknownKeys` 默认行为。
- 通过 hook 上游序列化逻辑保留未知字段。
- 绕过能力探测、认证、未知字段禁写、LKG、回读校验或回滚的强制写入入口。
- 对 Q9 B 方案宣称与严格版本白名单具有相同的数据安全保证。

## Further Notes

- 当前分析基线为 VoiceAssist `8.2.70.8421`。
- 兼容策略和用户主动接受的残余风险记录在 ADR-0001。
- MiLink 入口、独立面板与 VoiceAssist 适配器的职责边界记录在 ADR-0002。
- 领域术语以仓库根目录的领域词表为准。
- 未知版本、调试重试和错误通知不可撤回属于用户已明确接受的残余风险；规格不得把这些风险描述为已消除。
- 仍需在实现前定点确认 MiLink 页面注入位置和复用的导出 ContentProvider。
